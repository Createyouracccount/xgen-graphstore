# ADR-003 — graphstore = 그래프 저장소 **라우터** (단계적)

- **Status**: Accepted (2026-08-17). **ADR-002("router deferred")를 대체**한다.
- **한 줄**: "어떤 DB든 꽂고, XGEN이 무증상 오동작 없이 동작한다"를 코어 정체성으로. 라우터를 **단계적(R1→R2→R3)** 으로.

## Context
목표가 "인터페이스+백엔드+팩토리"에서 **"어떤 DB가 들어와도 라우팅으로 문제없이 동작"** 으로 승격됐다.
ADR-002는 라우터를 "두 번째 백엔드가 생기면"으로 미뤘으나, 이제 라우터를 **기반 개념**으로 잡는다.

## 정직한 현실 인식 (이 ADR의 핵심 — 라우터가 못 하는 것)
라우터는 **①올바른 백엔드를 고르고 ②못하는 연산을 조용히 깨지지 않게** 보장한다.
라우터는 **반쪽 구현된 백엔드를 완성하지 못한다.** 즉 "문제없이 동작"은 2층이다:

| 층 | 책임 | 이 ADR |
|---|---|---|
| 라우팅·능력계약·명확차단 | **라우터**(graphstore) | R1에서 확보 |
| 각 백엔드의 실제 계약 구현(SPARQL↔Cypher 등) | **백엔드별 작업**(DEBTS H) | 라우터가 대신 못 함 |

따라서 라우터의 진짜 가치는 **백엔드 능력 공백을 명확한 에러로 드러내** 무증상 오동작을 0으로
만드는 것(프로젝트 '회색지대 기본값 금지' 원칙과 정합). "완전 동작"은 백엔드 완성도에 비례한다.

## Decision — 단계적 라우터

### R1 (지금) — 레지스트리 + 능력계약 + 명확차단  ← **기반**
- **레지스트리**: `register_backend(name, factory)`. 어떤 DB든 등록하면 `create_store` 로 선택.
  팩토리 if/elif 제거 → 코어 수정 없이 백엔드 추가.
- **능력계약**: 각 백엔드가 `CAPABILITIES`(frozenset) 선언 — fulltext/named-graph/owl/ttl/raw 등.
- **명확차단**: 미지원 연산은 `CapabilityError`(백엔드·능력·DEBTS 지목). `supports()`/`require_capability()`
  로 호출 전 introspection 가능. 단일 활성 백엔드.
- **제약**: 완전성은 백엔드별 구현에 달림. Protocol 얇음(§G-Protocol)은 병행 과제.

### R2 (다음) — 능력기반 멀티백엔드 라우팅
- 여러 백엔드 동시 등록·활성. 연산을 **능력 보유 백엔드로 라우팅**(text:query→Fuseki, 그래프순회→Neo4j).
- **제약(반드시 선결)**: (a) *정본 문제* — 어느 store가 진실인가? (b) *데이터 동기화* — 두 store가
  같은 그래프를 갖게 유지하는 비용. (c) 쓰기 일관성·부분실패. R1의 능력계약이 라우팅 표를 만든다.

### R3 (미래) — 듀얼라이트 / 테넌트 라우팅
- 쓰기를 N백엔드 복제(마이그레이션·HA), 테넌트/그래프별 분기. 다중 라이브 인프라·충돌해소 전제.

## Consequences
- ADR-002 대체. 백엔드는 이제 `CAPABILITIES` 선언이 **필수**(미선언 시 능력검사 생략=단정 불가).
- `create_store` 는 라우터의 선택 함수. 공개 표면 유지(하위호환).
- R2 착수 조건: ≥2 백엔드가 호환 데이터를 보유 + 정본/동기화 정책 확정.
